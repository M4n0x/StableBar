Configure all of it.

Edit the bar where it is. Drag widgets between positions, take one off with −, and add one with + right where it should go. Changes save as you go, with Undo.

Every widget, style and popup is also a setting, per display and per kind of screen, in Settings or in plain JSON. StableBar applies the file when you save it, and keeps the last working bar if a change is invalid.

Tiling, natively. Workspaces come straight from AeroSpace, yabai or OmniWM, with app icons or one item per window, and update in place instead of recreating windows.

Workspaces in the guide

Window managers

  • AeroSpace and OmniWMWorkspace, monitor, window and focus events, live. Reconnects when the window manager restarts.
  • yabaiSpaces, windows and displays, refreshed by yabai signals.
  • One item per windowWindow titles in the workspace; click one to focus it.
  • No tiling managermacOS Spaces, and windows kept clear of the bar.

Configuration

  • On the bar itselfDrag, add and remove widgets where they sit, with Undo.
  • JSON with a schemaCompletion and validation in your editor.
  • Every styleFonts, colors, padding, corners and borders, per widget or per theme.
  • Per kind of screenIts own layout, size and theme on the laptop or a monitor.
  • ProfilesA different bar on battery, in dark mode or for one app.

Popups

Any widget can open a popup. Build it from rows, columns, text, graphs, lists, buttons, sliders, toggles and search fields, filled with the widget's data.

Any script is a widget

A widget can run any command that prints text or a JSON object. Refresh it on a timer or on events, and give it a popup with graphs, lists and controls.

The command line queries and edits the running bar, and other tools can send it events.

Create a widget
widgets/disk.shsh
#!/bin/sh
used=$(df -h / | awk 'NR == 2 { print $5 }')
printf '{"text":"%s","icon":"internaldrive"}' "$used"
config.jsonjson
{
  "id": "disk", "type": "script",
  "position": "right", "interval": 300,
  "command": "~/.config/stablebar/widgets/disk.sh"
}

The Store

Add widgets other people wrote, from Settings or the bar’s +, without writing a script. Before anything runs, StableBar shows what a package does: the commands it runs, the hosts it contacts and the macOS permissions it uses.

Checked on the way in. Every Store package is open source, and the Store builds and publishes it, not its author. A maintainer reads each version that runs commands, and StableBar checks every download against its SHA-256. Tokens stay in your Keychain, and versions stay pinned until you choose another.

Your team’s own widgets. Host a private source for packages that can’t be public, and invite your team with a join link. A stablebar:// link opens one package’s page in StableBar.
